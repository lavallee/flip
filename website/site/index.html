The gap

A final report is not the research record

Deep-research systems can return fluent, cited reports while leaving important branches unsearched, presenting one side of a question, or attaching citations that only partly support the prose. Six weeks later, a URL list and a polished answer cannot tell the next agent what was actually checked, what remained weak, or which follow-on question the evidence opened.

Recent independent benchmarks make the gap concrete. On 100 open-web tasks, the best system evaluated by LiveDRBench reached 0.55 overall F1 and the systems covered only about half of the necessary search queries [C8]. DeepTRACE's dated August 2025 snapshot evaluated 303 questions and 2,727 system-query samples; deep-research configurations were one-sided on 54.7%–94.8% of debate queries, while citation accuracy ranged from 31.4%–79.1% [C9].

flip does not make a model reason better by itself. It makes the route taken—and the routes still owed—durable, inspectable, and continuable.

What changes

Keep the investigation, not just the answer

01

Work the question

Follow-on questions, corroboration gaps, closer reads, recomputations, failed probes, narrower and adjacent answers, reopen conditions, and bounded continuation work survive the session.

02

Know what can be relied on

Actual source material is kept in custody. Capture and judgment remain separate. Leads, hypotheses, beliefs, assertions, verified claims, bounded nulls, and rejections can coexist without being flattened into one score.

03

Outlive the agent

Stable ids, named actors, append-only events, and bounded generated views let another agent or person continue without reconstructing the research from chat history—or silently overwriting how it changed.

At rest

Plain files are the handoff protocol

A flip notebook is an Open Knowledge Format v0.2 knowledge bundle at rest—not an export target [C6]. Every source, claim, decision, question, and session is one Markdown page with YAML frontmatter and an immutable id. Raw captures and hashes establish custody; events are append-only JSONL; generated views provide the hot state.

Open the same directory in Git, Obsidian, any Markdown editor, or an OKF consumer. Export it as BagIt, CSL JSON, render JSON, or a policy-filtered public OKF copy. Public export can withhold private source custody and event history; the workflow still owns source rights and licensing decisions.

Before you adopt it

The honest case against

The strongest objection is that this is ceremony. Source grading and claim metadata can raise the cost of every turn without improving what an agent concludes. A careless model can fill fields carelessly.

The answer is structural, not magical. Grading is a separate recorded act by a named actor. Ungraded sources count toward nothing. flip doctor exposes gaps and inconsistencies. That makes carelessness inspectable; it does not prevent it.

Observed use is not comparative effectiveness

The public examples show real notebook behavior, correction, long-running work, and honest unresolved states. No controlled test yet shows that flip-backed agents produce better conclusions than agents without notebooks. The measured claim today is narrower: on one 507-page notebook, cold orientation through generated views cost about 40K tokens, motivating bounded frontier views—not a blanket claim that a CLI always uses fewer tokens.

The OKF profile and spec remain drafts

flip's provenance vocabulary has not been submitted to, reviewed by, or endorsed by OKF maintainers. The spec is draft v0.21, not 1.0 or frozen. Migration exists because the format has moved and may move again.
